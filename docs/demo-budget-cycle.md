# Демонстрация предела запусков на PR

- **Статус:** учебный сценарий
- **Дата:** 2026-11-22
- **Запрос:** issue #14

На этом PR показываются два канала обратной связи агента и предел
запусков на один PR. Механика описана в
[`.github/workflows/opencode.yml`](../.github/workflows/opencode.yml):
job `opencode` (шаг «Check run budget») считает попытки по истории
Actions **до** вызова модели, job `report` публикует отказ без модели
и без секрета агента.

## Правила бюджета

- Лимит — 3 допущенных запуска `/oc` на один issue/PR.
- Попытка — завершённый job агента `opencode (PR #N)`, в котором шаг
  `Run opencode` не был пропущен. Re-run, таймаут, отмена и любой сбой
  этого шага тоже расходуют попытку, даже если до модели дело не дошло
  (например, доступ к модели выключен): по API это не отличить.
- Отказ по бюджету и сбой до шага `Run opencode` (нет ключа) попытку
  не тратят.
- Счётчик хранится в истории Actions — источник, который токен агента
  не может переписать. Комментарии без `/oc` (в том числе ответы агента)
  на бюджет не влияют.
- Отчёт показывает попытки, израсходованные **до** отказа: сама отказная
  попытка модель не вызывает и в счётчик не входит, поэтому при лимите 3
  отчёт печатает «3 из 3», а не «4 из 3».
- Новый issue или PR получает новый бюджет.
- Счётчик видит прогоны, созданные после мержа исправления имён job
  (PR #19): у тикетов со старыми прогонами, включая этот PR, счёт
  начинается заново.

## Сценарий демонстрации

1. Общий комментарий в обсуждении PR с `/oc` (событие `issue_comment`)
   — попытка 1.
2. Ещё один общий `/oc` — попытка 2.
3. Re-run одного из прогонов, где агент запускался (или третий `/oc`),
   — попытка 3. Re-run отказного прогона попытку не тратит.
4. Следующий `/oc` (четвёртая попытка) — агент не вызывается. Job
   `report` публикует комментарий «Нужен человек» с причиной
   `limit_exhausted`, использованными попытками (3 из 3), фактическим
   head SHA PR и ссылкой на логи.

## Свидетельство

Ссылка на прогон с отказом фиксируется в issue #14: она подтверждает,
что после исчерпания бюджета модель не вызывалась, а отчёт содержит
SHA и логи. Отчёты с причинами `timeout`, `infra` и `agent_failed` на
этом PR не демонстрируются — их условия описаны в коде job `report`.
