# Демонстрация предела запусков на PR

- **Статус:** проведена
- **Дата:** 2026-11-22
- **Запрос:** issue #14

На этом PR показываются два канала обратной связи агента и предел
запусков на один PR. Механика описана в
[`.github/workflows/opencode.yml`](../.github/workflows/opencode.yml):
job `opencode` (шаг «Check run budget») считает попытки по истории
Actions **до** вызова модели, job `report` публикует отказ без модели
и без секрета агента.

## Правила бюджета

- Лимит — 3 допущенных запуска `/oc` на один issue/PR.
- Попытка — завершённый job агента `opencode (PR #N)`, в котором шаг
  `Run opencode` не был пропущен. Re-run, таймаут, отмена и любой сбой
  тратят попытку, только если шаг `Run opencode` уже начался, даже если
  до модели дело не дошло (например, доступ к модели выключен): по API
  это не отличить.
- Отказ по бюджету, а также сбой или отмена до шага `Run opencode` (нет
  ключа, ошибка GitHub API в шаге бюджета) попытку не тратят.
- Счётчик хранится в истории Actions — источник, который токен агента
  не может переписать. Комментарии без `/oc` (в том числе ответы агента)
  на бюджет не влияют.
- Отчёт показывает попытки, израсходованные **до** отказа: сама отказная
  попытка модель не вызывает и в счётчик не входит, поэтому при лимите 3
  отчёт печатает «3 из 3», а не «4 из 3».
- Новый issue или PR получает новый бюджет.
- Счётчик ищет job по точному имени `opencode (PR #N)` среди прогонов,
  созданных после открытия тикета. Прогоны до исправления имён job
  (PR #19) записаны с обрезанным именем `opencode (PR` и не совпадают,
  поэтому у тикетов со старыми прогонами, включая этот PR, счёт
  начинается заново.

## Ход демонстрации

Все запуски — общие комментарии в обсуждении PR с `/oc` (событие
`issue_comment`) после мержа PR #19, 2026-11-23, время UTC.

1. `/oc` в 08:58 — шаг бюджета упал на ошибке GitHub API (HTTP 502),
   отчёт с причиной `infra`; модель не вызывалась, попытка не
   израсходована
   ([прогон 45143007609, попытка 1](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45143007609/attempts/1)).
   Re-run того же прогона — попытка 1, бюджет «0 из 3» до запуска
   ([попытка 2](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45143007609/attempts/2)).
2. `/oc` в 10:51 — попытка 2, бюджет «1 из 3»
   ([прогон 45159874135](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45159874135)).
3. `/oc` в 11:06 — попытка 3, бюджет «2 из 3»
   ([прогон 45162080696](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45162080696)).
4. `/oc` в 12:46 (четвёртая попытка) — отказ: бюджет «3 из 3», шаги
   `Guard secrets` и `Run opencode` пропущены, модель не вызывалась
   ([прогон 45177498691](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45177498691)).
   Job `report` опубликовал комментарий «Нужен человек» с причиной
   `limit_exhausted`, попытками «3 из 3», head SHA PR `37f6a35` и
   ссылкой на логи.
5. `/oc` в 12:50 — снова отказ с «3 из 3», а не «4 из 3»: отказы бюджет
   не тратят
   ([прогон 45178028293](https://github.com/alexmyt/ai-for-developers-project-387/actions/runs/45178028293)).

## Свидетельство

В issue #14 приложена ссылка на прогон 45178028293 (шаг 5); первый
отказ — прогон 45177498691 (шаг 4). Оба подтверждают, что после
исчерпания бюджета модель не вызывалась, а отчёт содержит причину,
попытки, SHA и логи.

Другие причины отчёта на этом PR тоже встретились, но вне плана демо:
`agent_failed` — 2026-11-22, до исправления счётчика (прогон
45021731015), `infra` — на шаге 1 выше. `timeout` не демонстрируется;
его условия описаны в коде job `report`.
